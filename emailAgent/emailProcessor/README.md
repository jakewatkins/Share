# Email Processor

A .NET 9 console application that processes categorized emails and generates daily reports.

## Overview

The Email Processor is designed to run unattended and handles the processing of emails that have been categorized or classified. It reads email files from a specified directory, processes them according to business rules, posts them to handlers, and generates daily HTML reports.

## Features

- **Email Processing**: Processes JSON files containing categorized emails
- **Whitelist Support**: Handles emails from whitelisted addresses differently
- **Category Handlers**: Routes emails to appropriate handlers based on classification
- **Daily Reports**: Generates HTML reports with email summaries
- **LLM Integration**: Uses external LLM service for email summarization
- **Azure Table Storage**: Integrates with Azure Tables for whitelist and handler configuration
- **Archive Management**: Archives processed files automatically

## Configuration

Configure the application using the `settings.json` file:

```json
{
  "API-KEY": "your-api-key-here",
  "summaryPrompt": "Please provide a brief summary of the following email:",
  "LLMPath": "/usr/local/bin",
  "DailyReportPath": "./reports",
  "EmailTemp": "./temp",
  "ProcessedEmails": "./processed",
  "EmailArchive": "./archive",
  "StorageAccount": "DefaultEndpointsProtocol=https;AccountName=youraccountname;AccountKey=youraccountkey;EndpointSuffix=core.windows.net"
}
```

## Azure Table Storage

The application uses two Azure Tables:

### EmailWhiteList Table
- **Purpose**: Stores email addresses that require special handling
- **Fields**: name, email, includeInReport, handlerUrl
- **PartitionKey**: "DigitalValet"
- **RowKey**: GUID

### CategoryHandler Table
- **Purpose**: Maps email categories to handler URLs
- **Fields**: category, handlerUrl
- **PartitionKey**: "DigitalValet"
- **RowKey**: GUID

## Email Processing Flow

1. **Initialization**: Creates daily report file (deleting existing if present)
2. **File Discovery**: Scans ProcessedEmails directory for JSON files
3. **Email Processing**: For each email:
   - Check if sender is in EmailWhiteList
   - If whitelisted and includeInReport=true: Generate summary and add to report
   - If whitelisted with handlerUrl: Post email to whitelist handler
   - If not whitelisted: Check CategoryHandler for classification
   - If category handler found: Post email to category handler
4. **Archiving**: Move processed files to archive with .bak extension

## Daily Reports

Generated as HTML files in the format: `email-report-yyyyMMdd.html`

Contains a table with:
- **Email Subject**: Clickable link to the original email
- **Email Summary**: Generated by LLM service

## Email URL Generation

- **Gmail**: `https://mail.google.com/mail/u/0/#inbox/{id}`
- **Outlook**: `https://outlook.live.com/mail/0/inbox/id/{id}`

## LLM Integration

Uses external LLM CLI tool for email summarization:
```bash
{LLMPath}/llm -PF {PromptFile} -o {OutputFile} --no-tools ibm-granite/granite-4.0-1b
```

The application follows clean architecture principles with:
- **Services**: Business logic separation
- **Models**: Data transfer objects and entities
- **Dependency Injection**: Loose coupling and testability
- **Configuration**: External settings management
